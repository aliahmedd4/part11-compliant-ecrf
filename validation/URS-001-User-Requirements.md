## 1. Purpose and Conventions

This document states the user requirements for the eCRF. Each requirement is
**atomic** (one testable statement), **uniquely identified** (URS-nnn), assigned a
**risk-based priority** (Critical / High / Medium), and references the primary
21 CFR Part 11 / ALCOA+ driver. Verification is via the referenced qualification
(OQ/PQ); full tracing is maintained in **RTM-001**.

Priority key: **C** = patient safety / data integrity critical; **H** = high;
**M** = medium.

## 2. Access Control Requirements

| ID | Priority | Requirement | Regulatory driver |
|---|---|---|---|
| **URS-001** | C | The system shall support four distinct user roles: Investigator, Data Manager, Monitor, and Administrator. | §11.10(d),(g) |
| **URS-002** | C | The system shall enforce a role-based permission matrix on the server for every protected operation, independent of any user-interface control. A user shall not be able to perform an action they are not authorised for, even by calling the API directly. | §11.10(d),(g) |
| **URS-003** | H | The system shall enforce a configurable password policy (minimum length, character-class complexity, and prevention of recent-password reuse). | §11.300(a),(b) |
| **URS-004** | H | The system shall lock a user account after a configurable number of consecutive failed authentication attempts within a configurable window, refusing further logins until the lock expires. | §11.300(d) |
| **URS-005** | H | The system shall enforce a configurable session timeout and shall warn the user before the session expires due to inactivity. | §11.10(d) |

## 3. Data Integrity Requirements (ALCOA+)

| ID | Priority | Requirement | Regulatory driver |
|---|---|---|---|
| **URS-006** | C | The system shall record, for every change to clinical data, an audit entry capturing the user, a UTC timestamp, the field changed, the old value, the new value, and the reason for change. | §11.10(e) |
| **URS-007** | C | The audit trail shall be append-only: audit entries shall not be editable or deletable by any user or process through the application. | §11.10(e) |
| **URS-008** | C | The system shall not permit hard deletion of any record. Deletions shall be logical (soft delete), retaining the record and recording the deletion in the audit trail. | §11.10(c),(e) |
| **URS-009** | C | All timestamps written to records, audit entries, and signatures shall be generated by the server clock. Client-supplied timestamps shall never be persisted. | §11.10(e); ALCOA+ Contemporaneous |

## 4. Electronic Signature Requirements (Subpart C)

| ID | Priority | Requirement | Regulatory driver |
|---|---|---|---|
| **URS-010** | C | Executing an electronic signature shall require the signer to re-authenticate with username and password at the time of signing. | §11.200(a)(1) |
| **URS-011** | C | Each signature shall capture the printed name of the signer, the UTC date and time of signing, and the meaning of the signature (author, reviewer, or approver). | §11.50(a) |
| **URS-012** | C | Each signature shall be cryptographically bound to the content of the signed record such that any subsequent alteration of that content invalidates the signature. | §11.70 |
| **URS-013** | C | Upon signing, a record shall become read-only; it shall not be modifiable through the ordinary edit path. | §11.10(e) |
| **URS-014** | C | Modification of a signed record shall be possible only through an explicit amendment workflow that requires a reason for change, increments the record version, records the change in the audit trail, and preserves (invalidates, not deletes) the prior signature. | §11.10(e); §11.70 |

## 5. Clinical Functional Requirements

| ID | Priority | Requirement | Regulatory driver |
|---|---|---|---|
| **URS-015** | M | The system shall support one clinical study with a defined visit schedule and shall allow enrolment of subjects identified by a study-unique code. | ICH GCP |
| **URS-016** | M | The system shall support three form types: demographics, vital signs, and adverse events. | ICH GCP |
| **URS-017** | H | The system shall apply edit checks on data entry, including required-field checks, range checks, and cross-field consistency checks, rejecting non-conforming data and reporting the specific violation. | ALCOA+ Accurate |
| **URS-018** | H | The system shall provide a data-clarification query workflow supporting raise, respond, and close transitions, retaining the full history of each query, with transitions permissioned by role. | ICH GCP; §11.10(e) |
| **URS-019** | H | The system shall export the dataset together with an integrity checksum enabling a recipient to verify the exported data has not been altered. | §11.10(c); ALCOA+ |
